# 3초영어 통합 개선 구현 보고

작성일: 2026-11-07. 대상 버전: Android **0.6.0 / versionCode 15**, 학습 화면 **v4.5.0**, Worker **v10**. 현재 코드 기준이며 실제 배포·단말 검증은 마지막 항목에서 별도로 구분한다.

## 1. 다섯 개선사항 구현 결과

| 요청 | 구현 |
| --- | --- |
| 가리고 다시 말하기 즉시 전환 | 화면을 즉시 다시 그리고 마이크 준비를 시작한다. 카운트다운 없이 실제 ready 이벤트 뒤에 ‘듣는 중’을 표시한다. 중복 실행을 막고 화면 이동/프로필 변경 시 이전 요청을 취소한다. |
| 오답 후 재시도 최대 5점 | 즉시 재시도와 뒤에 다시 나오는 문제에 같은 문제 그룹 ID를 유지한다. 최초 오답 0 XP, 이후 성공 총합 최대 5 XP. 중복 응답·동기화 재병합으로 더 지급하지 않는다. 최초 정답 20 XP, 힌트를 본 최초 정답 15 XP와 별도 일일 목표 보너스는 유지한다. |
| 발화 후 대기 단축 | 단일 마이크 PCM을 공식 Azure SDK로 전달한다. 실제 연결 준비를 끝내고 시작음을 들려준 후 녹음한다. 인식된 단어와 확정 구간으로 종료를 판단하며 불완전한 구간은 더 기다린다. PC 합성 음성의 짧은 완성 문장 3건에서 발화 뒤 대기 620/620/640 ms를 측정했다. 기존 1,400 ms의 절반 미만이다. 네트워크와 문장 중간 쉼까지 같은 시간을 보장하지 않는다. |
| 문장별 숙련도와 출제 조절 | 프로필별 0~100 숙련도를 저장한다. 80 초과 문장은 드물게 복습하고, 오래 안 본 문장·새 문장·반복 오답의 출제 가중치를 높인다. 표현 전체의 빈도에도 반영한다. |
| 선택형 의미 중심 판정 | 프로필 설정에 정확도 중심/의미 중심을 추가한다. 기본값은 기존 정확도 중심. 의미 중심은 OpenAI 전사 후 명확한 사례는 로컬 판정하고, 애매한 사례만 추가 의미 비교를 한다. 오류·불명확한 발화는 통과시키거나 숙련도를 깎지 않고 재시도를 안내한다. |

기존 학습 순서, 원문 확인·다시 듣기·따라 말하기·내 목소리 듣기·단어장 및 성인용 정확도 중심 경험은 유지한다.

## 3. 새 설정과 데이터 구조

| 키/구조 | 역할 |
| --- | --- |
| `learning_active_v1`, `learning_profiles_v1` | 현재 학습자 ID와 기기 내 프로필 목록. 기존 기록은 `legacy`의 기존 키에 보존 |

| `sentence_mastery_v1` | `{version:1,events:{<attemptId>:{id,en,t,order,ok,retry,delta}}}`. 이벤트 정렬·중복 제거 후 문장별 점수 재계산 |
| `practice_log_v1` 추가 필드 | 시도 ID, `attemptGroupId`, `rewardVersion:2`, `rewardCap`, `firstWrong`, `retry`로 문제 보상 총합 관리 |

프로필 이름은 로그인 인증이 아니다. 다른 학습자는 다른 동기화 닉네임을 사용해야 한다. 전환 중 도착한 이전 결과를 새 학습자에게 기록하지 않는다. 기존 기록을 새 숙련도로 소급 추정하지 않으며 새 시도부터 누적한다.

## 4. 숙련도 계산

문장 정규화 키별 시작값 0, 범위 0~100. 각 유효 시도에 다음 값을 반영한다.

| 결과 | 변화 |
| --- | ---: |
| 힌트 없이 최초 정답, 신규 소개 문장 아님 | +18 |
| 처음 보거나 힌트를 본 뒤 최초 정답 | +10 |
| 재시도 정답 | +4 |
| 오답 | −20 |
| 중복 요청·오류·무음·판정 불가 | 변화 없음 |

문제 보상 5 XP 상한과 숙련도 +4는 별개다. 동일 시도는 두 계산에 다시 반영하지 않는다. 숙련도 100에서 복습 오답이면 80이 되어 다음 출제 우선순위가 높아진다.

## 5. 출제 빈도

- 미출제 문장 가중치: **4**.
- 숙련도 **80 초과**: `0.08 + min(3, max(0, 미복습일수−7)/15)`. 최근 숙달 문장은 크게 줄이고 7일 이후부터 늘린다. 0이 되지 않는다.
- 숙련도 **80 이하**: `(1.2 + (80−점수)/80×1.8) × (1 + min(5,연속오답)×0.6 + min(5,누적오답)×0.1)`.
- 표현 프레임도 후보 문장의 평균 가중치를 반영해 문장 하나만 가진 익숙한 표현의 반복을 줄인다. 기존 난이도·선택 표현·초보용 짧은 문장 범위는 유지한다.

이는 확률 가중치이며 특정 회차의 출제를 보장하지 않는다.

## 6. 판정 모드별 흐름

정확도 중심은 기존 음성 인식과 `travelGrade()` 기준을 사용한다. 지원되는 새 Android 앱은 서버가 실시간 경로를 제공할 때 단일 마이크의 PCM을 Azure SDK로 스트리밍한다. 실제 인식 단어가 목표 단어 수에 도달한 경우 빠른 종료를 허용한다. 미완성 구간의 여유·최대 녹음 한도를 유지하고 최종 전사만 채점한다. 목표 문장 자체를 인식 힌트로 보내지 않는다.

의미 중심은 최대 25초/1 MiB의 PCM WAV를 `/practice-ai/transcribe`로 보낸다. 목표 답안을 전사 힌트로 전달하지 않는다. 동의 표현·정확한 답·명백한 부정/항목/수량 변경은 로컬 판정하고, 나머지는 `/practice-ai/judge`의 엄격한 구조화 결과를 확인한다. 낮은 확신·비정상 JSON·거부·시간 초과는 정답으로 추정하지 않는다. 기존 Azure 발음 점수는 별개다.

실제 완료 단어를 확인한 경우 빠른 무음 기준 650 ms, 미완성 구간 2,200 ms, 인식 근거가 없는 기존 경로 1,400 ms를 사용한다. Azure SDK 구간 무음은 100 ms, 부분 결과 안정화 기준은 1이다. 짧게 나뉜 인식 구간은 이어 붙이고 확정 전사만 채점한다. 부분 결과로 정답을 추측하지 않는다. 연결 준비 5초·미사용 준비 연결 8초 한도를 두며 실제 녹음 ready 이후에 말하기 시간 제한을 시작한다.

실시간 오류는 같은 원본 WAV로 기존 Azure 경로를 한 번만 사용하고 5분간 실패한 실시간 경로를 피한다. 이 복구에 OpenAI 보조 호출을 추가하지 않는다. 준비 중 취소·권한 거절은 시작음이나 추가 녹음을 실행하지 않는다. 어린이의 긴 휴지·말더듬·축약 표현·소음은 실기기 검증이 필요하다. 짧은 동의 표현은 목표 단어 수보다 적어 더 기다릴 수 있다. 의미 중심의 녹음 전용 경로는 인식 단어 근거가 없어 기존 1,400 ms를 유지한다.

## 7. OpenAI 모델과 API

| 용도 | 구현 |
| --- | --- |
| 실제 음성 전사 | `gpt-4o-mini-transcribe`, `/v1/audio/transcriptions`, 영어 힌트만 사용 |
| 애매한 의미 비교 | `gpt-5-nano`, `/v1/chat/completions`, 엄격한 JSON Schema, `reasoning_effort:minimal`, 출력 최대 400 토큰, `store:false` |
| 기존 Android AI 대화 | `PlanClient`의 `/v1/responses`와 로그인 계정 선택 모델 유지 |

확인 시점에 전사 mini와 GPT-5 nano는 deprecated 상태이나 아직 제공된다. 전사 mini 종료 예정일은 2027-02-26이다. 실제 활성화 전과 종료 전에 지원·가격·대표 발화 정확도를 재확인해야 한다. [공식 음성 API 안내](https://developers.openai.com/api/docs/guides/speech-to-text), [GPT-5 nano](https://developers.openai.com/api/docs/models/gpt-5-nano)

## 8. 기존 연결 재사용

`PlanClient`의 ChatGPT OAuth 연결·AndroidKeyStore 암호화 보관은 기존 AI 대화에서 유지한다. 이 로그인만으로 음성 API 권한·조직 연결·Pro 제공 크레딧이 생긴다고 가정하지 않는다. 의미 판정은 기존 Worker의 `OPENAI_API_KEY` 비밀정보 구조를 재사용하며 확인된 조직·프로젝트를 요청 헤더에 명시한다. 앱에 별도 API 키 입력·보관 시스템을 만들지 않았다. [GPT 연결 감사](gpt-connection-audit.md)에 근거와 서버 설정을 정리했다.

## 9. 소유자가 직접 해야 하는 크레딧 설정

1. 자격을 충족한 Pro 구독 소유자가 ChatGPT **설정 → 결제 → API 크레딧 혜택**에서 받을 API 조직을 확인하고 활성화한다.
2. 그 조직의 **Billing → Credit grants**에서 실제 지급·남은 제공 크레딧·만료일을 확인한다. Pro $200의 전체 주기 명목액은 $200이나 첫 지급액은 다를 수 있다.
3. 해당 조직의 전용 프로젝트와 서버 키를 확인한다. 제공액만 쓰려면 조직의 유료 잔액·결제·자동 충전 구성을 소유자가 직접 확인한다. 프로젝트만 나누면 조직 잔액이 분리되지는 않는다.
4. 감사 문서에 따라 조직/프로젝트·확인액·만료일·24시간 이내 확인 시각·최대 $5 월 예약 한도를 서버에 설정한 뒤에만 활성화한다. 기본값은 비활성이다.

이 작업은 계정 연결/지급을 대신 확인하지 않았고 결제 수단·유료 충전·자동 충전·크레딧 플래그를 변경하지 않았다. 공개 상태의 `balanceVerified:false`는 실제 잔액을 자동 조회하지 않는다는 뜻이다. `creditsVerified:true`도 소유자 확인 기록이며 실제 잔액 보증은 아니다. [공식 Pro API 크레딧 안내](https://help.openai.com/en/articles/20001626-api-credits-benefit-for-eligible-chatgpt-subscriptions)

## 10. 예상 비용과 비용 절감

[공식 가격](https://developers.openai.com/api/docs/pricing) 기준 전사 mini는 추정 분당 $0.003으로 5초 약 **$0.00025**, 10초 약 **$0.0005**다. GPT-5 nano는 입력 100만 토큰 $0.05·출력 $0.40이며 500 입력 + 80 출력이면 약 **$0.000057**다. 추가 비교를 생략하면 그 비용은 0이다.

중복 요청 ID/입력 해시로 결과를 최대 10분 재사용한다. 무음·명확한 사례는 호출을 줄이고 자동 유료 재시도는 하지 않는다. 요청별 시간·예상비용과 프로필별 기기 사용량을 표시한다. 서버는 호출 전 STT $0.00125/뜻 확인 $0.001를 보수적으로 예약하며 불확실한 실패에도 되돌리지 않는다.

예상치와 예약 합계는 실제 결제액·남은 크레딧과 다르다. KV는 원자적 저장소가 아니어서 지역/동시 요청의 비용 상한과 중복 방지를 완전히 보장하지 못한다. 공개 경로에 새 사용자 인증을 추가하지 않았으므로 대규모 공개 서비스의 강제 비용 방어에는 인증과 원자적 예약이 더 필요하다. 기존 `/stt2`·다른 앱의 비용은 새 합계에서 제외된다. 원음은 KV에 저장하지 않으며 요청 해시·전사 결과는 10분 보관한다.

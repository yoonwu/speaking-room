## 표현을 꺼내는 힘에 따라 넓어지는 연습

처음 시작하는 학습자는 기존 표현 중 다음 **10개**부터 연습한다. 새 예문 데이터셋을 추가한 변경이 아니다.

| 시작 표현 | ID |
| --- | --- |
| Can I get ~? | `travel_can_i_get` |
| Can you ~? | `travel_can_you` |
| Can I / we ~? | `travel_can_i_we` |
| Do you have ~? | `travel_do_you_have` |
| Where is ~? | `travel_where_is` |
| How much ~? | `travel_how_much` |
| Pay by card | `travel_pay_by_card` |
| Have a reservation | `travel_have_reservation` |
| I can't find ~ | `travel_cant_find` |
| Is there ~? | `travel_is_there` |

핵심은 내용 단어를 모두 맞혔는지와 별도로 **표현을 바로 꺼냈는지**다. 표현 익숙함은 적격한 최근 최초 음성 답변 5회로 계산한다.

| 해당 답변의 표현 | 표현 익숙함 계산에 넣는 점수 |
| --- | --- |
| 표현이 맞고 두 시간 기준을 모두 충족 | 10 |
| 표현은 맞지만 시간 기준 초과 | 5 |
| 이번 표현과 다른 표현 | 0 |

5회 점수 합계를 항상 5로 나눈다. 아직 답하지 않은 회차는 0점이다. 빠른 표현 성공 1회는 2/10, 4회는 **8/10**이므로 우연히 한 번 맞혀 새 표현이 열리지 않는다. 표현만 맞고 내용 단어를 틀린 답도 완전한 정답과 동일하게 표현 익숙함에 반영한다. 느린 표현 성공만 반복하면 최대 5/10이다.

- 실제 시간 근거가 있는 `timingVersion:2`의 힌트 없는 최초 음성 답변만 계산한다. 소개 답안 따라 말하기·힌트·직접 입력·즉시 재시도·같은 문제의 재출제·시간 근거 없는 과거 로그는 적격 5회를 채우거나 기존 점수를 밀어내지 않는다.
- 한 표현이 처음 8/10에 도달하면 다음 기존 표현 하나를 영구적으로 연다. 같은 표현으로 점수가 떨어졌다가 다시 올라가도 추가 해제하지 않는다. 각 원본 표현별 해제 크레딧을 한 번만 보관한다.
- 해제 순서는 포함 여부 → 만나는 장소 → 추천 → 다시 천천히 말해달라는 요청 → 이것이 맞는지 확인 → 변경 요청 → 하고 싶은 일 → 짐 맡기기 → 해야 하는지 확인 → 의미 확인 → 방법 → 길 찾기 → 질문 요청이다. 코드의 `TRAVEL_PROGRESS_ORDER`를 기준으로 총 23개까지 열린다.
- 이미 소개했거나 `seen>0`인 기존 활성 표현은 계속 사용할 수 있다. 비어 있는 비용·출제 기록만으로 잠긴 표현을 열지 않는다. 사용자가 2단계로 미룬 9개는 해제 대상에 포함하지 않는다.
- 한 번 열린 표현은 현재 점수가 내려가도 남는다. 프로필별 `speakingroom:expression_progress_v1`의 `earned`, `unlocked`, `legacy` 집합을 동기화할 때 합쳐 중복 크레딧을 막는다. 로그만 남고 해제 저장이 누락된 경우 과거의 검증된 점수 도달 이력으로 복구한다.

출제는 현재 표현 점수를 직접 반영한다. **현재 8점 이상은 가중치 0.15**, 아직 익히는 표현은 **1~2**로 뽑고 같은 10회 안의 출제 수를 추가로 반영한다. 약한 표현이 한 루틴에서 다시 나올 수 있어 익숙한 표현을 반드시 한 번씩 모두 돌지 않는다. 점수가 8 아래로 내려가면 보통 연습 비중으로 돌아온다. 과거의 내용 단어 정답·누적 비용이 이 표현 출제를 계속 억누르지 않는다.

성장 기록의 기존 상세 화면에서 표현별 현재 점수와 열린 수를 확인한다. 홈의 ‘익숙해진 표현’ 수도 현재 8/10 이상인 표현을 센다. 내용 단어까지 맞히는 문장 숙련도와 익힌 단어 기록은 따로 유지한다. 기존 전체 정답 비율도 **‘문장 전체 정답률’**로 표시해 표현을 맞힌 답의 익숙함과 혼동하지 않게 했다. 20개 후보 답안은 활성화하지 않았으며 이번 변경에 새로운 학습 데이터셋 추가는 없다.

## 빠른 답의 시간 기준과 XP

빠른 답은 다음 **두 조건을 각각** 만족해야 한다.

1. 문제를 보고 마이크를 누르기까지 **3,000ms 이내**.
2. 실제 마이크가 준비된 뒤 목소리를 시작하기까지 **1,500ms 이내**.

권한·앱 준비·시작음·네트워크 인식 결과를 기다린 시간을 학습자의 반응 지연으로 세지 않는다. 예를 들어 누르기까지 2,800ms, 목소리 시작까지 1,400ms이면 합계가 4,200ms여도 빠른 답이다. 합계 3초를 요구하는 규칙이 아니다. 양쪽 경계값 3,000ms·1,500ms도 포함한다.

새 로그와 문장 숙련도 이벤트에는 `timingVersion:2`, `tapMs`, `speechStartDelayMs`, 두 시간 조건의 플래그, `responseMs`, `speedEligible`을 보관한다. 기존 v1 기록의 문장 숙련도·XP는 유지하되 새 표현 진행의 두 시간 근거를 소급해서 만들지 않는다. 음성 시작은 같은 녹음 PCM의 발화 위치이며 버튼 터치만으로 추정하지 않는다.

| 최초 답변 | 빠른 답 | 일반 답 |
| --- | --- | --- |
| 문장 전체 정답 | 30 XP | 15 XP |
| 표현만 맞고 내용 단어가 틀리거나 빠짐 | 15 XP | 10 XP |

XP 4단계는 유지한다. 첫 부분 정답의 10/15 XP는 해당 문제의 한도를 사용하며 즉시·뒤의 재시도 정답이 XP를 더 주거나 기존 XP를 줄이지 않는다. 첫 답이 표현도 틀린 0 XP이면 이후 성공한 재시도 전체를 합쳐 최대 5 XP다. 일일 10회 목표 +25 XP는 별도다. 부분 정답의 문장 숙련도 변화는 0이고 완전 정답·익힌 단어 수를 늘리지 않는다. 표현 진행과 문장 숙련도·XP를 하나의 점수로 섞지 않는다. 이 계산에 새 GPT 요청을 추가하지 않는다.

## 연결을 기다리지 않고 같은 음성을 보존하는 마이크

기존 사전 연결을 유지하면서 **사용자가 누른 뒤 실제 녹음은 SDK 네트워크 연결과 병렬로 시작**한다. 새 앱은 `practiceImmediateCapture` 기능을 알린다. 마이크 권한은 사용자 행동에 따라 확인하고, 권한이 없는 백그라운드 준비가 OS 권한 창이나 마이크를 열지 않는다.

SDK 준비 동안 같은 PCM을 제한된 FIFO에 쌓아 연결되면 순서대로 전달한다. 녹음은 마이크 하나이며 같은 PCM으로 원본 WAV와 발화 시작 위치를 유지한다. SDK 연결 실패도 이미 말한 원본 WAV를 잃거나 새 마이크를 요구하지 않도록 기존 인식 경로로 넘긴다. 이전 비동기 응답과 중복 준비는 세대·취소 상태로 무효화한다. 사용하지 않은 준비는 기존 만료로 닫는다.

준비 응답을 받았다는 이유만으로 녹음 중으로 표시하지 않는다. 실제 AudioRecord 준비의 `onReady`가 전달될 때 마이크 준비 완료로 전환한다. 화면 이동·프로필 변경·취소가 이전 발화를 채점하거나 다른 학습자에게 기록하지 않도록 기존 방어를 유지한다.

### 운영 SDK에 실제 PCM을 보낸 측정

작업 폴더 `outputs/native-immediate-capture-062-results.jsonl` 및 관련 이벤트 로그를 확인했다. **데스크톱에서 공식 SDK와 실제 PCM 반복 입력을 사용한 측정이며 Android 휴대폰 마이크 실측이 아니다.** 아래 시작 지연은 PCM 입력 루프의 시작 지연이다.

| 입력 | PCM 루프 시작 | SDK 연결 준비 | 인식 결과 |
| --- | --- | --- | --- |
| cold: 물 요청 | 17ms | 3,067ms | `Can I get some water?` |
| cold: 짐 맡기기 | 4ms | 1,811ms | `Can I leave my bags here?` |
| cold: 휴대폰 찾기 | 5ms | 1,600ms | `I can't find my phone.` |
| cold: 중간 900ms 쉼 | 7ms | 2,198ms | `I can't find my. My phone.` |
| 준비 완료 뒤 1초 기다린 warm 입력 | 준비·의도한 대기 뒤 입력 | 1,727ms | `Can I get some water?` |

깨끗한 세 문장과 warm 문장은 기준 문장과 일치했다. 중간 쉼 문장은 `my`가 반복됐지만 의도한 단어는 모두 남았다. 5개 모두 단어 보존을 확인했으며 5개 모두 기준 문자열과 완전히 같았다는 뜻은 아니다. cold에서는 연결되기 전 PCM 80~130개 프레임을 보존했다. SDK 준비 시간이 길면 답변 결과가 늦을 수 있으며 이번 측정으로 휴대폰의 모든 발화나 2초 이내 결과를 보장하지 않는다.

# 3초영어 0.6.1 내부 테스트 출시와 v4.6.1 화면 수정

작성일: 2026-11-07. Play 앱은 **0.6.1 / versionCode 16**, 설치 파일에 포함된 학습 화면은 **v4.6.0**이다. 별도 학습 화면 수정 **v4.6.1**의 최소 앱 버전도 **minimumNativeVersion 16**이다.

**0.6.1/code 16은 2026-11-07 18:15 KST에 Play 내부 테스터에게 제공됨을 확인했다.** 출시 번호는 11이며 작업 폴더의 `outputs/play-0.6.1-published.png`에 Console 상태를 보관했다. 공개 프로덕션 출시는 아니다. 서명한 AAB·APK와 포함된 v4.6.0의 검증은 Node 173개·Android JVM 65개다. 이후 JavaScript 보상 수정 v4.6.1은 Node 182개를 통과했으며 2026-11-07 18:26 KST에 별도 웹 배포까지 확인했다. 실제 휴대폰 검증은 완료되지 않았다.

이전 0.6.0/code 15와 v4.5.0의 테스트·실제 SDK 측정·게시 이력은 [기존 통합 보고](integrated-improvements-2026-11-07.md)에 보존한다. 아래 설치 파일 검증과 이후 웹 수정 검증을 구분한다.

소개 문장, 힌트/답안 보기, 직접 입력, 즉시 다시 말하기, 재출제된 같은 문제는 빠른 정답으로 졸업시키지 않는다. 기존 XP·문장 숙련도 이벤트·프로필·동기화 기록은 보존하고, 과거의 `perfect`만 보고 3초 기록을 소급 생성하지 않는다. 느리게 맞혀 점수가 100이 되어도 아직 익히는 중이면 보통 출제 비중을 유지한다.

## 별도 웹 수정 v4.6.1 — 표현만 맞힌 답의 보상

소스 커밋은 `a5cac183aad2584ca1983982af92f5599d9f676f`다. 이 변경은 JavaScript 화면 배포이며 새 네이티브 빌드를 만들지 않는다. **위 AAB·APK 안에는 v4.6.0이 그대로 들어 있다.** v4.6.1은 2026-11-07 18:26 KST 배포 확인을 마쳤으며 code 16 이상 앱이 학습 화면을 내려받아 적용한다.

| 최초 답변 | 실제 시간 근거가 있는 힌트 없는 3초 이내 음성 답변 | 일반 답변 |
| --- | --- | --- |
| 문장 전체 정답 | 30 XP | 15 XP |
| 표현 틀은 맞고 내용 단어가 틀리거나 빠짐 | 15 XP | 10 XP |

표현만 맞힌 답은 `ok:false`를 유지한다. 문장 숙련도 변화는 **0**이며 정답 수·빠른 문장 정답 수·익힌 단어를 늘리지 않는다. 연속 빠른 정답과 완전히 익힌 상태는 해제하고 내용 단어를 다시 연습한다. 기본 말하기 난이도에는 표현 성공으로, 속도에는 실제로 빠르게 꺼낸 표현만 빠른 성공으로 반영한다. 새 로그와 숙련도 이벤트는 `expressionOnly`, `fastExpression`을 함께 보관한다.

첫 부분 정답의 10/15 XP는 해당 문제의 보상 한도를 모두 사용한다. 즉시 정답을 말하거나 같은 문제가 뒤에 다시 나와도 추가 XP를 주거나 기존 점수를 줄이지 않는다. 표현도 맞히지 못한 첫 오답은 0 XP, 이후 부분/전체 정답 재시도는 합계 최대 5 XP다. 기존 XP·프로필·동기화 기록은 유지한다. 소개·힌트·직접 입력·즉시 재시도에는 3초 보너스를 주지 않는다. 시간 근거는 v4.6.0과 같으며 별도 GPT 요청을 추가하지 않는다.

전체 Node **182/182** 통과, 실패·오류·건너뜀 0. 로그는 작업 폴더 `outputs/retrieval-461-node-tests.log`다. 실제 화면과 모의 네이티브 시간 근거를 사용한 표현 부분 정답 **15 XP** 확인은 `outputs/expression-partial-461.png`에 보관했다. 이는 실제 휴대폰 마이크 실측이 아니다. GitHub Actions **42359338013** 성공, 라이브 descriptor 리비전·최소 앱 버전 16 및 주요 파일 8개의 SHA-256/크기를 **2026-11-07 18:26 KST에 확인했다**. 증거는 작업 폴더 `outputs/web-v4.6.1-published.json`이다.

20개 후보 답안은 현재 학습·정답 자료에 활성화하지 않았다. 다음 표현군 방향을 검토 중이며 이번 수정에는 데이터셋을 추가하지 않았다.

## 네이티브 연결과 기록 계약

- code 16은 `practiceBackgroundPreparation`, `practiceSpeechTiming`을 비롯한 실제 지원 기능을 상태 응답으로 알린다. 웹은 기능 확인 뒤에만 백그라운드 준비와 새 시간 근거를 사용한다.
- `preparePracticeFast`는 실제 녹음과 분리된다. 권한이 없는 백그라운드 요청은 준비되지 않은 상태로 반환하고, 사용자 요청에 의한 권한 거절도 별도 녹음을 열지 않는다. 인식 연결이 준비된 뒤 시작음을 재생하고, 시작음이 끝난 뒤 같은 준비 연결로 마이크 하나를 연다.
- 새 녹음 결과의 `speechStartOffsetMs`, `captureDurationMs`는 해당 WAV가 있을 때만 반환한다. 재시작·취소·초기 주변 소음 보정 시 이전 발화 시점을 재사용하지 않는다.
- 같은 문장의 준비 요청은 진행 중 연결을 공유하며, 일치하는 녹음이 한 번만 소비한다. 준비 연결을 사용하지 않으면 기존 8초 만료가 닫는다. 화면 이동·프로필 전환·취소는 이전 준비와 녹음 결과를 무효화한다.
- `practice_log_v1`과 `sentence_mastery_v1`의 새 이벤트는 `timingVersion:1`, `responseMs`, `withinThreeSeconds`, `speedEligible`, `fast`를 보관한다. 음성 시작 위치 자체를 별도 계정·토큰으로 저장하지 않는다. 프로필별 키와 기존 선택적 동기화 범위를 유지한다.
- 어려운 단어는 기존 프로필별 `answer_vocab`에 누락 제안 횟수·단어 연습 성공 수·최근 시각을 함께 보관한다. 선택적 동기화에도 포함하며 최근 정보와 최대 누적 통계를 병합한다. 음성 인식에서 빠졌다는 사실을 음소별 발음 오류 진단으로 표시하지 않는다.
- 이 보상·시간·숙련도 계산은 로컬 처리다. 이를 계산하려고 새 GPT 요청을 보내지 않는다. 선택형 의미 중심 API의 별도 서버 게이트는 [기존 연결 감사](gpt-connection-audit.md)의 규칙을 유지한다.

새 웹 배포는 code 16 이상만 적용한다. 이전 앱에 화면 파일만 덮어써 새 마이크 기능이 생겼다고 표시하지 않는다. 기존 0.6.0 앱은 호환되는 이전 화면을 유지하며 새 기능은 Play 앱 업데이트 뒤 사용한다.

## 최종 검증과 서명 절차

1. 모든 웹·네이티브 변경과 어려운 단어 연습을 마친 뒤 소스를 고정한다. `versionName 0.6.1`, `versionCode 16`, 두 `WebUpdater` 생성자의 16, `APP_VERSION v4.6.0`, HTML 자산 버전과 `minimumNativeVersion 16`을 함께 확인한다.
2. 저장소 루트에서 전체 Node 회귀를 실행한다. 최종 개수·실패·건너뜀을 실제 출력으로 기록한다.

   ```powershell
   $releaseTests = Get-ChildItem android/tests -Filter '*.test.cjs' | Select-Object -ExpandProperty FullName
   node --test $releaseTests
   ```

3. 기존 JDK 17·Gradle 8.11.1·SDK 36과 캐시로 `bundleRelease assembleRelease testDebugUnitTest lintRelease assembleDebug`를 실행한다. 기존 업로드 키와 Windows DPAPI 보호 비밀번호만 사용한다. 보호 문자열의 끝 줄바꿈을 제거해 읽고 `SR_UPLOAD_*` 환경변수를 해당 빌드 프로세스에만 설정한다. 비밀번호를 출력·임시 파일·Git에 남기지 않고 종료 시 환경과 임시 메모리를 정리한다. 새 키를 만들지 않는다.
4. JVM 결과 XML의 전체 테스트 수·실패·오류·건너뜀을 합산한다. `UP-TO-DATE`라는 문구만 보고 새 테스트가 통과했다고 기록하지 않는다. 같은 고정 소스에서 수행된 최종 결과와 대조한다. 출시 lint의 오류와 경고를 따로 기록한다.
5. 실제 AAB의 `base/manifest/AndroidManifest.xml`을 Android의 고정된 `aapt2-proto`로 읽어 패키지 `com.speakingroom.voice`, 0.6.1/code 16을 확인한다. 작업 폴더의 `VerifySpeakingRoomBundle.java` 기대값도 0.6.1/code 16으로 갱신했다. APK는 `aapt2 dump badging`으로 같은 패키지·버전을 확인한다.
6. AAB는 `jarsigner -verify`, APK는 `apksigner verify --print-certs`로 확인하고 실제 업로드 인증서 SHA-256이 두 파일 모두 `E18C255BC89DFDAFCDDD2A06BBA425C1930DE8AD14400A6D7B0BFD33BFB02E17`인지 대조한다.
7. AAB와 APK 안의 `index.html`, `practice-data.js`, `practice-ai.js`, `practice.js`, `home-support.js`, `android-native.js`, `practice.css`, `privacy.html`이 고정 소스와 바이트 단위로 같은지 확인한다. 새 자산이 있으면 네이티브 `bundleWebApp`과 `scripts/android-web-release.cjs`에 모두 포함한다.
8. 검증된 파일을 작업 폴더 `outputs/speaking-room-0.6.1-play.aab`, `outputs/speaking-room-0.6.1-release.apk`에 복사하고 SHA-256·크기·소스 해시·실제 검사 결과를 `outputs/speaking-room-0.6.1-verification.json`에 기록한다. 0.6.0 파일이나 그 해시를 새 후보로 재사용하지 않는다.
9. 루트 담당자가 기존 Play 내부 테스트 트랙과 불변 웹 배포를 진행한다. 이후 Console의 제공 상태, 라이브 웹 descriptor의 리비전·최소 앱 버전·파일 해시를 확인하고 게시 시각을 기록한다. 내부 테스트를 공개 프로덕션 출시로 표현하지 않는다.

실제 Android 휴대폰의 마이크·권한·스피커 검증은 별도다. 이전 합성 PCM/데스크톱 SDK 지연 측정이나 이번 모의 브리지 테스트를 새 휴대폰 실측 또는 모든 발화의 응답 시간 보장으로 보고하지 않는다.
